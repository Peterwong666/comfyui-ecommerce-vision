# 提示词库（P5-08）

> 面向**电商商品视觉量产**的结构化提示词库。目标不是「写得好」，而是**可检索、可组合、可统计、可回归**。
> 使用说明与贡献规范见 [`docs/sop/prompt_guide.md`](../../docs/sop/prompt_guide.md)。

## ⚠️ 四条使用前必读

1. 🚨 **klein 链路上严禁写权重 `(word:1.2)`。**
   源码证据：`KleinTokenizer` 显式传 `disable_weights=True`（`comfy/text_encoders/flux.py:153,169`）。
   **不是"无效"，是污染提示词** —— 括号、冒号、数字会原样进入分词成为 token。
   `t2i_v1`（SDXL）可正常使用权重；`flux2_klein_t2i_v1` **严禁**。
   详见 [`../../docs/sop/prompt_guide.md`](../../docs/sop/prompt_guide.md) §1.1 与 `debug_log.md` G7。
2. **klein 链路上反向词无效，且无处可填。**
   ① 图上：官方 Distilled 子图用 `ConditioningZeroOut` 把负向置零；
   ② 接口上：该工作流的参数 Schema **未暴露 `negative_prompt` 字段**。
   所以不是"填了不起作用"，是**填不进去** —— 想「排除某物」只能靠：① 正向增强 ② 局部重绘 ③ 人工筛选。
   反向词包是 **SDXL 链路（cfg 7~8）与人工审查清单** 的主力工具。
   **不要为 klein 补这个字段**（那是"看起来能用"的陷阱）。
3. **材质词 = 商品真实性声明。** 写了「头层牛皮」就必须真的是牛皮，否则构成对商品的虚假描述。
4. **画面里的文字一律后期叠加。** 中文字形渲染错误率极高，且伪造品牌标识是法律红线。

## 标签体系

`tags` 为两级分类，第一级固定取自下表（便于统计与检索），第二级自由：

| 一级标签 | 含义 | 例 |
|---|---|---|
| `主体` | 商品本体名词 | `主体, 3C数码, 音频` |
| `属性` | 形态/颜色/呈现方式 | `属性, 形态, 呈现方式` |
| `画质` | 清晰度、保真、交付质量 | `画质, 保真, 结构` |
| `风格` | 调性与摄影语言 | `风格, 摄影棚, 白底` |
| `材质` | 材质与表面工艺 | `材质, 皮具, 牛皮` |
| `光影` | 布光、光位、色温、阴影 | `光影, 布光, 柔光` |
| `构图` | 占比、法则、视角、画幅 | `构图, 视角, 正视` |
| `形态` | 结构正确性（多在反向） | `形态, 变形` |
| `结构` | 人体/零件的正确性 | `结构, 人体` |
| `合规` | 法律与平台红线 | `合规, 商标` |

`scenes` 取值固定为六种：`白底主图` / `场景图` / `氛围图` / `材质特写` / `模特图` / `包装图`
（`全部` 仅用于反向与通用词条）。

## 字段约定

原子词条（`positive` / `style` / `material` / `light` / `composition` / `negative`）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `<pack前缀>-<三位序号>`，**删除后编号不复用**（保证历史产物元数据可追溯） |
| `text` | ✅ | 中文提示词 |
| `text_en` | ✅ | 英文对照（SDXL 系底模对英文更敏感，可按底模切换） |
| `tags` | ✅ | 标签数组，第一级取自上文 |
| `scenes` | ✅ | 适用场景 |
| `priority` | ✅ | `1` 必填 / `2` 增强 / `3` 可选修饰 |
| `note` | ➖ | 踩坑提示（含 ⚠️ 标记的是高风险项） |
| `severity` | 反向专有 | `hit` 出现即判废 / `warn` 影响观感 / `soft` 轻微瑕疵 |
| `works_on` | 反向专有 | `cfg_gt_1` / `all`，见上文「必读 1」 |
| `morph_risk` | 风格专有 | `low` / `medium` / `high` 形变风险 |
| `budget` | 风格专有 | `low` / `medium` / `high` 算力开销 |

## 与代码/数据库的对接

| 目标 | 映射方式 |
|---|---|
| DB 表 `prompt_library`（`backend/app/models/asset.py:67`） | `title`=条目 `name` 或 `text` 摘要；`category`=第一级标签或电商品类；`positive`/`negative`=配方拼装结果；`tags`=`tags` 原样写入 |
| 参数模板库（P3-10，`assets/prompt_lib/templates/`） | 以 `scenes.yaml` 的 `recipes` 为输入，落成工作流预设 JSON |
| 提示词模板引擎（P5-09） | 读取 `slots_contract`：按 `order` 拼装、按 `max_terms` 截断、自动追加 `quality_tail` |
| 产物元数据（P3-11） | 必须记录 `recipe_id` + 使用的词条 `id` 列表，否则无法复现 |
