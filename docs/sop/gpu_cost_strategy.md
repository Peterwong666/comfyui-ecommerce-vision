# GPU 成本策略（autoDL）

> 商用级 = 成本可核算。GPU 机时是本项目最大的现金支出，必须像管预算一样管它。
> 规则核实日期：2026-09-15，来源：autoDL 官方文档（省钱绝招 / 快速开始 / 本地硬盘）。

## 1. 计费事实（官方原文核实）

| 规则 | 说明 |
|---|---|
| 计费起点 | 「实例状态显示**运行中**开始计费」 |
| 关机 | **停止计算计费**；如不使用请及时关机 |
| 数据盘 | **无论是否关机都计费**（存储费，远低于计算费） |
| 数据保留 | 关机后数据全部保存，开机无需重新配置 |
| ⚠️ 释放风险 | **连续关机 15 天实例将被释放** |

## 2. 三种模式对比

| 模式 | 配置 | 价格 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| **有卡模式** | 128 核 / 1TB / RTX 4090 24G | 按 GPU 单价（见控制台） | 全部：出图、评测、压测 | — |
| **无卡模式** | **0.5 核 / 2GB 内存 / 无 GPU** | **¥0.1/小时** | 下载模型、写代码、编辑文档、单进程脚本 | ❌ 出图 ❌ ComfyUI ❌ docker-compose（PG+Redis+MinIO 超出 2GB）❌ 任何 GPU 推理 |
| **关机** | — | **0 计算费**（仅数据盘存储费） | — | 什么都做不了 |

**无卡模式的其他限制**（官方文档）：
- 同一主账号**同时只能有一个**无卡模式实例
- 无卡模式会**释放 GPU**，切回正常模式时若卡被其他用户租用，**可能没卡可用** → 需等待或克隆实例
- 切换方式：**必须先关机**，再以无卡模式开机 → **会中断所有运行中的进程**

## 3. 各阶段该用哪种模式

| 阶段 | 任务 | 推荐模式 | 理由 |
|---|---|---|---|
| W1 | 下载模型（SDXL / FLUX.2 / 控制模型） | **无卡** | 纯网络 I/O，完全不需要 GPU |
| W1 | P1 产品文档（MRD / PRD / 画像 / 原型） | 无卡 或 **关机** | 不消耗服务器资源 |
| W1-W2 | 代码骨架（FastAPI 单体部分） | 无卡 | 单进程可跑 |
| W1-W2 | P2-09 docker-compose（PG + Redis + MinIO） | **有卡** | 2GB 内存不够 |
| W2-W5 | P3 工作流开发、P4 控制体系 | **有卡** | 必须出图验证 |
| W6-W8 | P8 质量评测、P9 压测 | **有卡** | 必须 |
| 每天收工 | — | **关机** | 0 计算费 |

## 4. 省钱纪律

1. **下载一律在无卡模式下进行。** 下载动辄 1-2 小时，用 GPU 单价计费是纯浪费。
2. **不用就关机**，不要挂着空转。
3. **别频繁切换有卡/无卡。** 每次切换都要关机重启（中断进程），且切回时有「没卡」的风险。
   P3 之后进入连续出图期，保持有卡更省心。
4. **关机不超过 15 天**，否则实例被释放。长期不用时，确保重要资产已进 GitHub。
5. **脚本必须支持断点续传**（aria2c `-c`）。无卡模式随时可能重启，没有续传就白下。

## 5. 踩过的坑

| 坑 | 现象 | 对策 |
|---|---|---|
| **文件看着下完了其实是空的** | aria2c 带 `-k 1M` 会**预分配**磁盘空间，`ls -la` 显示已满 Size，但实际只下了一小部分 | 判断完成与否要看 **aria2c 日志里的 `Download complete`** 或 `.aria2` 控制文件是否消失，**不要看文件大小** |
| 切换模式会杀进程 | 关机重启后下载进程没了 | 脚本用 `-c` 续传，重启后重跑即可 |
| 无卡模式内存只有 2GB | 起多个服务会 OOM | 一次只跑一个任务；docker-compose 延后到有卡模式 |
