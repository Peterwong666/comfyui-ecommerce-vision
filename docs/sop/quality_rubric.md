## 0. ⚠️ 本文件**不**证明什么（必须先读）

| # | 本文件**不**声称 | 说明 |
|---|---|---|
| 1 | **这是一份「定义」，不是「结论」** | 它只规定「怎么打分」。**本文件没有对任何一张真实产物打过一次分** |
| 2 | **锚点是「设计值」，不是在真实产物上标定出来的** | §3 每个档位的判据是我按 `negative.yaml` 的 `severity` 与 `composition.yaml` 的设计口径**写出来的**。它们没有经过任何真实产物的校准 |
| 3 | **没有做评分者一致性检验** | 没有让两个人在同一批图上独立打分后比对。**本文件的「分数」目前不具备跨评分者的可复现性** —— 这是它最大的局限 |
| 4 | **不提供任何数字** | 本文件里**没有**通过率、良品率、平均分。跑分是 P8-04/P8-05 的事 |
| 5 | **不定义良品率的公式** | 良品率口径以 `docs/prd/tracking_plan.md:154,169` 为准：`image_adopted 数 / succeeded 图片数`。⚠️ `PRD_v1.md:548` 写的「采纳数 / **生成数**」是**笔误**，`tracking_plan.md` §5.1 明确把「生成数做分母」列为错误做法 |
| 6 | **不引入新的判废词汇** | 判废 / 可重跑 / 可接受三档**直接沿用** `negative.yaml` 的 `hit` / `warn` / `soft`。本文件**不另造**「严重不合格」这类词 |

> 一句话：**本文件是「尺子的刻度说明」，不是「测量结果」。**
> 在有人真的用它打过一批图、并做过一致性检验之前，
> 任何「按本 rubric 得分 X」的说法都只是**一个人一次性的主观判断**。

## 1. 适用范围与**不适用**的场景

| | 内容 |
|---|---|
| ✅ 适用 | **生成的商品图产物**（`t2i_v1` / `flux2_klein_t2i_v1` / `i2i_v1` / `inpaint_v1` / `upscale_v1` 的产物） |
| ✅ 适用 | 人工抽检（P8-04）的逐张打分、golden set（P8-01）的将来回填 |
| ❌ **不适用** | 用户上传的**原始素材**评分 —— 那不是我方生成质量 |
| ❌ **不适用** | 性能/成本评价 —— 属 P9 |
| ❌ **不适用** | 自动质检（P8-03）的算法输出 —— P8-03 可以**调用**本 rubric 的阈值，但本文件不描述算法 |
| ❌ **不适用** | 跨工作流横向比较「谁更好」 —— 五条工作流目标不同（换底 vs 重绘 vs 放大），同一把尺子横比会产生误导 |

### 1.1 链路差异：**必须**在报告里写明

`negative.yaml:5-13` 定死了一条链路事实：

| 链路 | 反向词 | 对本 rubric 的影响 |
|---|---|---|
| CFG>1（SDXL：`t2i_v1` 等） | ✅ 有效 | 打分**不因**链路而变，但「为什么没命中 hit」的**原因分析**不同：SDXL 链路可用反向词，klein **不能** |
| CFG=1（klein 蒸馏） | ❌ 无效，且 Schema **无 `negative_prompt` 字段** | ⚠️ klein 链路**没有任何反向词兜底手段**。对 klein 产物打分时，**不要**把「建议加反向词」写进改进建议 —— 那在该链路上是**假建议** |

> ⭐ **本 rubric 评的是「产物」，与链路无关；但「怎么改」与链路强相关。**
> 这条区分不写清楚，就会出现「让 klein 加反向词」这类无效建议（`defect_kb.md` §2 的硬规矩）。

## 2. 前置规则：`hit` **一票否决**

`negative.yaml:24` 的定义是「**hit = 出现即判废（人工质检直接淘汰）**」。

因此本 rubric 的第一条规则是**否决式**的：

> 🔴 **只要命中任意一条 `severity: hit`，该张产物直接判废，总分记 1 分，
> 不再计算其余三个维度。**

理由：`hit` 里包含合规/法律类红线（伪造品牌标识 `neg-027`、画面文字 `neg-026`、
水印 `neg-025`、NSFW `neg-030`、暴力 `neg-031`、儿童商业化 `neg-032`），
以及商品保真的结构类红线（`neg-011` 结构畸变、`neg-012` 比例失调、
`neg-013` 多出零件、`neg-014` 缺少部件）。
这些**都不能靠「其它维度分数高」来抵消** —— 一张构图完美但带着伪造商标的图，
在商用上比一张构图平庸但合规的图**更糟**。

⚠️ **`hit` 清单的当前规模（实测，不手抄印象）**：

| severity | 条数 | 出处 |
|---|---|---|
| `hit` | **20** | `negative.yaml` 实测（`grep -c 'severity: hit'` 会得到 21，多出来的 1 条在 `:17` 的**注释**里，不是条目） |
| `warn` | **18** | 同上 |
| `soft` | **2** | `neg-010` 色带断层 · `neg-036` 边框 |

> ⚠️ `negative.yaml:17` 那行注释里的 `severity: hit` 会让 `grep -c` 多数一条。
> 引用条数时请用 YAML 解析结果，不要用 `grep -c`（这是本轮实际踩到的坑）。

## 3. 四个维度 × 1-5 分

### 3.0 计分总览

| 维度 | 评什么 | 一票否决? |
|---|---|---|
| **D1 技术缺陷** | 画质层：模糊/噪点/伪影/畸变/过曝 | 是（`hit`） |
| **D2 构图** | 主体占比/留白/裁切/视角/串味 | 否（但 `neg-037`/`neg-038`/`neg-039` 是 warn） |
| **D3 一致性** | 与参考商品图 + 同批次之间的结构/色彩/材质一致 | 否（结构类 `hit` 会触发 §2） |
| **D4 商用可用度** | 能不能直接上线：合规、边缘、文案位、后处理成本 | 是（合规类 `hit`） |

总分 = 4 个维度**各自独立**的 1-5 分（**不做加权求和**）。
**报告时必须四个分数一起给**，只写一个总分等于把「为什么」丢掉
（`debug_log.md` T1-1 的教训：**没有口径的数字比没有数字更危险**）。

> ⚠️ 本 rubric **刻意不做加权**。加权系数需要真实评测数据来标定，
> 而现在**一次真实评测都没跑过** —— 此时定权重就是凭空造一个看起来精确的数字。

### 3.1 D1 · 技术缺陷（画质层）

| 分 | 可操作判据 | 锚点（`negative.yaml`） |
|---|---|---|
| **5** | 100% 放大无可见模糊、噪点、压缩伪影、畸变。画面干净 | **0 条** severity 命中 |
| **4** | 存在轻微瑕疵，**不影响可用**，无需重跑 | 仅命中 `soft`（`neg-010` 色带断层 / `neg-036` 边框） |
| **3** | 存在影响观感的瑕疵，**建议重跑**，但主体与材质仍可辨识 | 命中 **1–2 条** `warn`（`neg-003` 噪点 / `neg-004` JPEG 伪影 / `neg-005` 过锐 / `neg-007` 死黑高光 / `neg-009` 过饱和 / `neg-016` 透视 / `neg-017` 对称 / `neg-018` 悬浮 / `neg-020` 纹理重复 / `neg-021` 反射 / `neg-022` 投影 / `neg-023` 多光源 / `neg-024` 光溢出 / `neg-033` 低质量 / `neg-034` 最差质量 / `neg-037` 裁切 / `neg-038` 串味 / `neg-039` 人物误入） |
| **2** | 同类瑕疵**在同一区域叠加**（如过曝 + 高光溢出 + 边缘融化同时出现在产品边缘），或命中 **≥3 条** `warn` | ≥3 条 `warn`，或同一区域多条 `warn` 叠加 |
| **1** | 🔴 **判废** | 命中**任意** `hit`（见 §2） |

**可操作判据补充**：
- 判定「过曝」看**产品边缘是否与白底粘连**（`neg-040` 是白底主图的特有失败模式，属 `hit`）。
- 判定「材质失真」看**高光形态**（金属应是窄而亮的反射，塑料是宽而漫的）—— 与 `neg-019` 对应，属 `hit`。
- 判定「结构」看**部件计数**（`neg-013` / `neg-014`，均属 `hit`）与**比例**（`neg-012`，属 `hit`）。
  ⚠️ 这三条都落在 `hit` 上 → 一旦命中即判废，所以 D1 的 2 分与 1 分之间有一条**很宽的沟**。

---

### 3.2 D2 · 构图

| 分 | 可操作判据 | 依据 |
|---|---|---|
| **5** | 主体占比落在 **65%–80%**；居中度/三分点对齐准确；四周留白均匀；主体完整无裁切；视角单一一致；无无关元素 | `composition.yaml` cmp-001 `note`（「主流电商平台主图要求主体占比较大，建议 65%-80%」） |
| **4** | 占比略偏（55%–65% 或 80%–85%），或留白略有偏差；主体完整、视角一致 | `composition.yaml` cmp-002（主体 50% 四周留白）作为下一档参照 |
| **3** | 占比明显偏离（<50% 或 >90%），或留白显著不均；但主体完整可辨 | `composition.yaml` cmp-003（特写）与 cmp-001 之间的落差 |
| **2** | 主体被裁切（`neg-037`）/ 出现非目标品类元素（`neg-038`）/ 人物误入（`neg-039`） | 三条均为 `warn` |
| **1** | 主体出画或无法辨认主商品；画面被无关元素主导 | 属 D1/D3 的结构类 `hit`，同时触发 §2 |

⚠️ **占比要求随画幅与平台而变**：竖版主图与横版场景图的合理区间不同。
本档位默认按**白底主图**写；评其它场景（`scenes.yaml` rc-004~rc-016）时
**必须在记录里写明场景 id**，否则 65%-80% 这个数会被误用。

### 3.3 D3 · 一致性

**比对对象**（逐项对齐）：
① 结构（部件数与相对位置）② 比例 ③ 颜色 ④ 材质微表面 ⑤ logo / 文字位置（如有）
⑥ 同批次内其它图的光影与色温

| 分 | 可操作判据 |
|---|---|
| **5** | 六个比对项**逐项对齐**；同批多张的光影、色温、背景一致（`light.yaml` 文件头的「同批次复用同一套光影词」纪律成立） |
| **4** | 主要特征一致；差异仅限**不影响辨识**的微表面/高光位置 |
| **3** | **一处**可见差异（如某个部件形状略变），不影响品类辨识 |
| **2** | **多处**差异，或颜色明显偏移；同批内出现可察觉的风格漂移（`defect_kb.md` D-37） |
| **1** | 商品被换成另一件/另一品类；或命中 `neg-011` 结构变形 / `neg-012` 比例失调 / `neg-013` 多出零件 / `neg-014` 缺少部件（四者均为 `hit` → 同时触发 §2） |

⚠️ **i2i / inpaint / upscale 的特别纪律**：
「**不该动的地方一个像素都不能动**」（`debug_log.md` §2.6 IP-2）。
放大与局部重绘的产物，D3 的权重**高于** D1 —— 因为它们的**唯一目的**就是保住原图，
画质再细腻，只要改了商品本身就不合格。
本 rubric **不给它们单独一套分数**（那会造成两套标准），但在记录里必须注明工作流。

---

### 3.4 D4 · 商用可用度

问的不是「好不好看」，而是「**能不能直接拿去上架**」。

| 分 | 可操作判据 |
|---|---|
| **5** | **可直接上线**。无任何合规类 `hit`；白底干净、产品边缘完整（未命中 `neg-040`）；文案位留白充足 |
| **4** | 需**轻微**后处理（裁切 / 微调色），不影响商品表达，**无需重跑** |
| **3** | 需**较多**后处理（换底 / 补光 / 修边缘），或**需重跑一次** |
| **2** | 重跑后仍不达标，或需**专业修图**才能用 |
| **1** | 🔴 **不可用**：命中合规/法律类 `hit` —— `neg-025` 水印 · `neg-026` 画面文字 · `neg-027` 伪造品牌标识 · `neg-030` NSFW · `neg-031` 暴力血腥 · `neg-032` 儿童商业化 |

⚠️ 这六条 `hit` 在 `negative.yaml` 里的 `works_on` 是 **`all`**（与 CFG 无关），
且 `neg-025` / `neg-026` 的 `note` 明确写了「**反向词不足以保证**，交付前需人工/后处理核查」。
**因此 D4 的 1 分不能靠「加强反向词」来避免** —— 它必须在**交付前**由人工/后处理兜住。

## 4. `severity` → 分数 的映射表（**唯一**的判废词汇来源）

| `severity` | `negative.yaml:24-26` 的定义 | 条数 | 对 **D1** 的作用 | 对 **D4** 的作用 | 处置 |
|---|---|---|---|---|---|
| **`hit`** | 出现即判废（人工质检直接淘汰） | **20** | **D1 = 1**（一票否决，见 §2） | 合规类 → **D4 = 1**；结构类 → 触发 §2 | 🔴 **淘汰**，不再计其余维度 |
| **`warn`** | 影响观感，可重跑（默认） | **18** | 每条 −1 档；**≥3 条 → D1 = 2** | 通常落在 4~3 档（需后处理或重跑） | 🟡 **重跑**（或后处理） |
| **`soft`** | 轻微瑕疵，可接受 | **2** | 至多降到 **D1 = 4**（不更低） | 不影响（**仍可上线**） | 🟢 **可接受** |

⭐ **本表是 rubric 与 `negative.yaml` 之间唯一的接口。**
不在本表里的词（如「严重」「一般」「轻微不合格」）**一律不使用** ——
另造词汇会让 rubric 与判废清单各说各话，而 `negative.yaml:17` 已明确
「`severity: hit` 的条目**即**判废标准」。

### 4.1 ⚠️ `warn` 升级阈值的状态：**提案，未校准**

「≥3 条 `warn` → D1 = 2」这个阈值**是我定的，没有任何数据支撑**。
它与 `quality_sampling_sop.md` §3.2 的 `warn` 升级规则同属**未校准的提案**。
校准需要真实评测数据（golden set 跑通后）。**在此之前，引用这个阈值必须带上「未校准」三个字。**

## 5. 打分作业流程（与 P8-04 的分工）

本文件**只定义刻度**。抽样比例、抽样方法、记录表模板、判读作业规范
（防疲劳误判）**全部**在 **`docs/sop/quality_sampling_sop.md`（P8-04）**。

打分时**必须记录**（否则分数不可追溯）：

| 必记项 | 为什么 |
|---|---|
| 产物文件 + 其 `wf_meta`（`workflow_id` / `version` / `seed` / `params` / 模型 hash） | 没带元数据的分数**无法归因**（FR-5.5 的可复现前提） |
| **工作流 id 与版本** | 五条工作流目标不同，且版本变化会让历史分数失效（`workflow_spec.md` 的版本纪律） |
| **链路**（SDXL / klein） | 决定「怎么改」的建议是否成立（§1.1） |
| **场景 id**（`scenes.yaml` rc-0xx） | 占比等阈值的合理区间随场景变（§3.2） |
| 命中的 `neg-xxx` 编号（逐条列出） | 这是分数的**依据**。只写「D1=3」等于没写 |
| 评分者 + 时间 | 未做一致性检验前，分数**只在该评分者内部可比** |
