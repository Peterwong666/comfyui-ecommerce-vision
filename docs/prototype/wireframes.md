## 0. 全局规范

### 0.1 布局框架

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏  Logo │ 工作台 批量 任务 画廊 模板 │        配额 用户▾  │  56px
├──────┬─────────────────────────────────────────────────────┤
│      │                                                     │
│ 侧栏 │              主内容区                                │
│ 200px│              max-width 1280px 居中                  │
│      │                                                     │
└──────┴─────────────────────────────────────────────────────┘
```

> V1 用**左侧栏 + 顶栏**而非纯顶栏：任务中心与画廊都需要按状态筛选，
> 侧栏能承载筛选器，避免每次都要开弹窗。

### 0.2 设计原则（来自 persona 与旅程的约束）

| # | 原则 | 依据 |
|---|---|---|
| 1 | **关键参数不超过 5 个可见** | 画像① 痛点「参数看不懂」（FR-2.3） |
| 2 | **任何等待都要有进度与预计时长** | GPU 并发=1，排队是常态（FR-2.6） |
| 3 | **模板必须带效果缩略图** | 旅程 3→4 是关键转化点（FR-2.2） |
| 4 | **失败必须可定位到具体某张** | 画像② 痛点「跑到第 30 张崩了」（FR-4.2） |
| 5 | **成本在提交前就要可见** | 画像② 与品牌方都关心成本（FR-3.3） |

### 0.3 通用组件

| 组件 | 用途 | 关键状态 |
|---|---|---|
| 任务状态徽章 | 显示 8 种状态 | pending 灰 / queued 蓝 / running 蓝闪 / retrying 橙 / succeeded 绿 / failed 红 / canceled 灰暗 / partial 橙 |
| 进度条 | 单张进度 / 批量完成数 | 带百分比 + 预计剩余时间 |
| 空状态 | 无数据引导 | 必须带「下一步做什么」的行动按钮 |
| 错误提示 | 失败原因 | 必须给人话 + 是否可重试（对齐 PRD §6） |
