# ADR-001 交付形态与首发场景

- 日期：2026-09-15
- 状态：已定

## 背景

岗位说明要求的本质是「能独立交付商用级 ComfyUI 生产体系」，而非「会用 ComfyUI」。
需要一个载体同时证明三件事：工作流能力、工程封装能力、产品化能力。

## 决策

**交付形态**：Web 平台 —— 前端 + API + 异步任务队列，ComfyUI 仅作为底层推理引擎。

**首发场景**：电商视觉 / 产品渲染（主图、场景图、细节图）。

## 备选方案与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Web 平台**（选定） | 最贴近商用；能完整展示产品 + 工程能力；天然支持批量与多用户 | 工作量最大，前端是主要不确定项 | ✅ |
| 纯 API + SDK | 开发量小、落地快 | 只有工程没有产品，作品集说服力弱 | ❌ |
| 工作流包 + 脚本 | 最轻，聚焦工作流本身 | 无「商用级」说服力，无法体现量产与平台能力 | ❌ |
| 桌面客户端 | 适合设计师个人 | 无法体现云端量产、多租户、成本与并发 | ❌ |

**为什么首发电商视觉**

| 场景 | 标准化程度 | 良品率可量化 | 周期 | 结论 |
|---|---|---|---|---|
| **电商视觉** | 高（主图/场景图范式固定） | 高（商品主体保真可直接判定） | 短 | ✅ V1 |
| IP 形象一致性 | 中 | 中（一致性有主观成分） | 中 | V2 |
| 场景合成 | 中 | 中 | 中 | V2 |
| AI 视频 | 低 | 低 | 长（显存压力最大） | V3 |

电商场景需求最标准化、最容易建立量化验收标准（商品有没有被改形、光影是否统一），
最适合作为「量产体系」的样板；把最难的（IP 一致性、视频）放到已经跑顺的体系之上。

## 代价与风险

- 前端工作量可能远超预期（风险 R7）。对策：P7-02「工作流驱动的动态表单」优先做，
  新增工作流不改前端；必要时砍 P7-09（管理后台）与 P7-10（响应式）保主线。
- 平台层会挤占工作流调优时间。对策：P3/P4（工作流与控制）在 W2-W5 优先保障，
  P6/P7（平台）从 W4 才启动，且 P8 质量评测提前到 W6 开始，留足两轮调优窗口。

## 复核时机

- W4 结束（M3 工作流可用）时复核：若工作流质量远低于预期，考虑缩减平台范围保质量。
- V1 发布后复盘，决定 V2 是否按既定顺序进入 IP 一致性。
