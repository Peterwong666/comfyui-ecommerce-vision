# ADR-002 开源策略与许可证

- 日期：2026-09-15
- 状态：已定

## 背景

代码要上传个人 GitHub 作为作品集，必须可公开访问、可被他人使用与验证。
但项目定位是「商用级」，而 AIGC 生态中最大的法律风险来自**模型权重的许可证**，而非代码。

## 决策

1. **自研代码与文档：MIT 许可证**（见仓库 `LICENSE`）。
2. **不 fork ComfyUI**：以独立进程方式通过其 HTTP/WebSocket API 调用，不修改、不分发其源码。
3. **模型权重不入库**：`.gitignore` 拦截全部权重格式；仓库只保留 `model_registry.yaml` 清单
   （含来源 URL、hash、许可证、评测分）。
4. **商用许可矩阵**：`docs/sop/license_matrix.md`，每个在用模型必须登记，
   **「许可未知」一律视为不可用**。

## 为什么选 MIT 而不是 Apache-2.0 / GPL

| 许可证 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **MIT** | 最宽松，采用门槛最低，作品集传播性最好 | 无专利授予条款 | ✅ |
| Apache-2.0 | 含专利授予，企业级形象更好 | 要求保留 NOTICE、声明变更，对使用者更重 | 备选 |
| GPL-3.0 | 与 ComfyUI 一致 | 传染性会劝退商业使用者，与「商用封装」定位冲突 | ❌ |

本项目价值在于展示能力，采用门槛越低越好，故选 MIT。

## ComfyUI 的 GPL-3.0 问题（关键）

ComfyUI 本体为 **GPL-3.0**。这对本项目的影响与应对：

| 使用方式 | 是否触发 GPL 传染 | 本项目做法 |
|---|---|---|
| fork 并修改 ComfyUI 源码后分发 | ✅ 触发，必须开源 | **不做** |
| 独立进程 + 网络 API 调用（SaaS 模式） | ❌ 一般不触发（未分发衍生作品） | **采用** |
| 引入 GPL 许可的自定义节点 | ⚠️ 节点在独立进程中运行，风险较低但需评估 | 节点引入需登记许可，GPL 节点单独标记 |

> 注意：本项目代码为 MIT，与 ComfyUI 的 GPL-3.0 并存是合法的 ——
> 二者是独立程序，通过标准网络接口通信，不构成衍生作品。
> 若将来要将平台**私有化交付给客户**（即分发），需重新做合规性评估。

## 代价与风险

- 风险 R4（模型商用许可踩坑）：影响极高。对策是强制登记 + 「未知即不用」。
- 风险 R12（敏感信息泄露）：推送前全仓库扫描（P11-11），`.gitignore` 已拦截 `.env` 与密钥格式。
- MIT 意味着他人可商用本项目代码而不回馈，这在作品集场景是可接受的代价。

## 复核时机

- 每次新增模型时（自动触发登记流程）。
- V1 发布前（P11-11）全量复查一次许可矩阵与仓库敏感信息。
- 若将来要做私有化交付（V2 ADR-007 相关），需重新评估 GPL 边界。
