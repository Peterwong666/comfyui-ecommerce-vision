# ADR-005 底模选型：SDXL 主 + FLUX.2 [klein] 4B 辅

- 日期：2026-09-15
- 状态：已定（基于当前信息，P5-02 评测后可能调整权重）

## 背景

V1 首发场景是电商视觉量产。底模决定三件事：画质上限、控制体系可用度、吞吐与成本。
选型不能只看画质，必须同时过三关：**商用许可证 × 可下载性 × 生态成熟度**。

## 决策

- **主底模：SDXL 1.0**（已就位，出图 12.0s @ 1024²/25步）
- **第二底模：FLUX.2 [klein] 4B**（Apache-2.0，下载中）
- **明确排除**：FLUX.1 [dev]、FLUX.2 [dev]、FLUX.2 [klein] 9B / 9B KV / 9B Base —— 均为 Non-Commercial

## 为什么是这两个

| 维度 | SDXL 1.0 | **FLUX.2 [klein] 4B** | FLUX.2 [dev] 32B |
|---|---|---|---|
| 许可证 | OpenRAIL++-M ✅ 商用 | **Apache-2.0** ✅ 商用 | ❌ Non-Commercial |
| 可下载性 | ✅ 公开 | ✅ 未 gated（自带 VAE） | ❌ gated（403） |
| 显存 | ~10GB fp16 | **约 8GB**（官方称 3090/4070 可跑） | 需 H100 级 / 重度量化 |
| 速度 | 12.0s @ 1024²/25步 | **亚秒级**（蒸馏，4 步） | 慢 |
| 控制生态 | **最成熟**（ControlNet / IP-Adapter / LoRA 齐全） | 新，生态待成长期 | 弱 |
| 编辑能力 | 需外接 inpaint 链路 | **原生支持单/多参考图编辑** | 支持 |

**分工逻辑**
- **SDXL 承担 V1 前四周的六条工作流**：因为 P4 的控制矩阵（ControlNet / IP-Adapter / LoRA）都建立在 SDXL 生态上，这是「可控性」的保证。
- **klein 4B 承担两件事**：① P5-02 的对比评测（画质与速度）；② 它原生的**多参考图编辑**能力，正是 V2「商品一致性 / 场景合成」最需要的东西 —— 用 SDXL 做这些要拼好多节点，klein 一个模型就够。
- 二者不是替代关系，是**分工关系**：SDXL 打「可控」，klein 打「一致性与效率」。

## 备选方案与取舍

| 方案 | 取舍 | 结论 |
|---|---|---|
| 只用 SDXL | 生态最稳，但拿不到新架构的画质与原生编辑能力 | 保守，V2 会吃亏 |
| 只用 FLUX.2 klein | 许可与效率最优，但控制生态（ControlNet 等）目前不如 SDXL 成熟，P4 风险高 | 激进，V1 不能赌 |
| 用 FLUX.1 schnell | 同为 Apache-2.0，但仓库 gated 取不到，且需单独解决 VAE | 已被现实排除（见 `项目进展.md` #7） |
| 引入 FLUX.2 dev 做画质对比 | 效果最好但是非商用，与项目定位冲突 | ❌ 不碰 |

## 代价与风险

- 维护两套模型的**参数模板与评测基线**，工作量翻倍。对策：工作流注册表天然支持多底模，`model_registry` 分组管理。
- klein 的控制生态若不成熟，V2 的「一致性」目标可能落空。对策：V2 启动前（W11）重新评估生态成熟度。
- ComfyUI v0.3.75 对 klein 的支持未经验证 —— 若不支持需升级 ComfyUI，会打破 P2-06 的版本锁定。
  对策：升级也是一次记录到 `versions.lock` 的正常变更，不是回退。

## 复核时机

- **P5-02 评测后（W3-W4）**：用 golden set 对比两者良品率与速度，确定 V1 默认底模。
- **V2 启动前（W11）**：评估 klein 的控制生态是否成熟到可以承接一致性场景。

## 勘误（2026-09-17 追加，原文保留不动）

- **「为什么是这两个 → 分工逻辑」里的「SDXL 承担 V1 前四周的六条工作流」一句**：
  本 ADR 写于 2026-09-15，当时的口径是「6 条工作流」。按 **ADR-008 裁定 1**
  （[`0008-v1-scope-reduction.md`](./0008-v1-scope-reduction.md)），`style_transfer_v1` **顺延 V2**，
  该口径在 V1 **不可能达成** ⇒ V1 实为 **5 条上线 + 1 条顺延**；此处「六条」应读作「**5 条 + 1 条顺延**」。
- **本文件其余内容（底模选型、排除项、备选取舍、代价与风险）不受影响** —— 勘误只涉及**计数口径**。
- ⚠️ **ADR 是历史决策记录，故此处只加注、不改正文**；口径的权威表述见 `0008-v1-scope-reduction.md`。
