## 2. 人力预算

### 2.1 投入结构

| 角色 | 内容 | 占比 |
|---|---|---|
| 产品经理 | MRD / PRD / 画像 / 流程 / 原型 / 埋点 / 复盘 | 25% |
| 后端开发 | 工作流内核 / 控制体系 / API / 队列 / 状态机 | 40% |
| 前端开发 | 工作台 / 任务中心 / 画廊 / 批量向导 | 20% |
| 测试与运维 | 压测 / 评测 / 环境复现 / 部署文档 | 15% |

> **1 人分饰 4 角**是本项目最大的资源约束。
> 直接后果：**任何角色缺位都会导致 V1 不完整** —— 例如只写代码不做评测，就无法证明良品率。

### 2.2 工时估算

| 项 | 数值 | 依据 |
|---|---|---|
| 计划周期 | 10 周（2026-09-14 ~ 11-22） | ADR-003 |
| 每周投入 | 6h × 6 天 = 36h | 已确认前提「全职，每天 6h+」 |
| 总可用工时 | 约 **360h** | 10 × 36 |
| 任务总数 | 约 146 | WBS |
| **平均每任务** | **约 2.5h** | 360 / 146 |

> ⚠️ **2.5h/任务是偏紧的均值**。实际分布不均：
> 简单任务（写一条 ADR）0.5h，重任务（六条工作流）可达 40h。
> 所以排期必须靠**关键路径优先 + 浮动分支延后**，不能平均用力。

### 2.3 已有投入（截至 2026-09-15）

| 日期 | 投入 | 产出 |
|---|---|---|
| 09-14 ~ 09-15 | 约 14h | P0 全部（8 任务）+ P2 的 4 任务 + P1 的 15 任务 |
| **累计进度** | **约 4% 工时，完成约 18% 任务** | 前期偏产品与基建，符合预期 |

## 3. GPU 预算

### 3.1 计费事实（已核实）

| 模式 | 价格 | 来源 |
|---|---|---|
| 有卡（RTX 4090 24G） | `待核实`（见控制台，通常按时计费） | autoDL 控制台 |
| 无卡 | **¥0.1/小时** | 官方文档 ✅ |
| 关机 | 0 计算费（仅数据盘存储费） | 官方文档 ✅ |

### 3.2 各阶段 GPU 需求

| 阶段 | 周 | 需要 GPU？ | 说明 |
|---|---|---|---|
| P0-P1 计划与产品定义 | W1 | ❌ | 纯文档，可关机/无卡 |
| P2 环境与基建 | W1-W2 | 🔶 部分 | docker-compose 需有卡（2GB 内存不够） |
| P3 工作流内核 | W2-W4 | ✅ | 必须出图验证 |
| P4 控制体系 | W3-W5 | ✅ | 必须出图调参 |
| P5 模型资产 | W2-W6 | 🔶 部分 | 模型评测需 GPU，文档整理不需要 |
| P6 平台服务化 | W4-W6 | ✅ | 需真实任务跑通 |
| P7 前端 | W5-W7 | 🔶 部分 | 联调需 GPU，纯 UI 不需要 |
| P8 质量评测 | W6-W7 | ✅ | golden set 必须跑 |
| P9 性能压测 | W7-W8 | ✅ | 8h 压测 |
| P10 数据监测 | W7-W8 | 🔶 部分 | 需真实流量 |
| P11-P12 文档与发布 | W8-W10 | ❌ | 纯文档 |

**结论**：**需要 GPU 的是 W2~W8，共约 7 周**。

### 3.3 成本估算（三种情景）

> `待核实`：GPU 单价需查控制台。以下用**假设单价**演示算法，
> 拿到真实单价后直接代入即可，结论随之修正。

假设 4090 单价为 **¥P / 小时**（待核实）：

| 情景 | 每日 GPU 时长 | 天数 | 无卡/关机时长 | 估算 |
|---|---|---|---|---|
| **乐观**（每天高效用 4h） | 4h | 49 天（7周） | 其余关机 | 4×49×P = **196P** |
| **中性**（每天 6h） | 6h | 49 天 | 其余关机 | 6×49×P = **294P** |
| **悲观**（每天 8h） | 8h | 49 天 | 其余关机 | 8×49×P = **392P** |

**加**：无卡模式时长（下载/写文档）约 60h × ¥0.1 = **¥6**
**加**：数据盘存储费（全程无论开关机）50G × 10 周 = `待核实`

### 3.4 省钱措施（已落地）

| 措施 | 效果 | 状态 |
|---|---|---|
| 下载一律无卡模式 | 省下数小时 GPU 单价 | ✅ 已执行（FLUX.2 下载中） |
| 写文档时关机/无卡 | 省下 W1 整周 GPU 费 | ✅ 已执行 |
| 不用就关机 | 避免空转 | ✅ 纪律已定 |
| 脚本支持续传 | 避免重下浪费 | ✅ aria2c `-c` |
| **不在有卡/无卡间频繁切换** | 避免「切回没卡」+ 白交切换成本 | ✅ 纪律已定 |

> **已经发生的实际节省**：本次 FLUX.2 klein 三件套（约 11GB）下载约 1.5h，
> 若用有卡模式是纯浪费；改用无卡模式成本 ¥0.15。

### 3.5 GPU 成本控制目标

| 指标 | 目标 | 测量 |
|---|---|---|
| 单张出图成本 | 可核算且显著低于垂直商拍按张报价 | P9-09 成本模型 |
| 开发期日均 GPU 费用 | 尽量压低，文档期趋近 0 | 成本记录表 |
| 空转浪费 | **0** —— 不出现「开着卡写文档」 | 自觉 + 记录 |

| IP-Adapter | ~1G | ✅ V1 必需 | ⬜ 待下 |
| LoRA ×N | 每个 50-200M | ⭕ Should | ⬜ 待定 |
| SAM / DWPose | ~1-2G | ⭕ Should | ⬜ 待定 |

**预估新增需求**：ControlNet + IP-Adapter 约 **8-15G**。

| 项 | 数值 |
|---|---|
| 当前剩余 | 31G |
| 预估新增 | 8-15G |
| 产物累积（V1 内测期） | 1000 张 × 1MB ≈ 1G |
| **剩余安全边际** | **约 15-22G** ✅ 够用 |

> ⚠️ **风险**：若后续要加 SD3.5 / Flux dev（23G+）等大模型，50G 数据盘会不够。
> 需提前决策：扩容数据盘 或 用完即删（模型归档到对象存储/外部）。

### 4.4 磁盘告警阈值

| 阈值 | 动作 |
|---|---|
| 数据盘剩余 < 10G | 告警，停止新模型下载 |
| 数据盘剩余 < 5G | 停止接收新任务（EX-4） |
